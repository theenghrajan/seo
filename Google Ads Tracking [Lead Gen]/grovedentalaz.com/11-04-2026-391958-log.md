### ❌ ROOT CAUSE: Contact form doesn't show at all on `/contact/?id=ppc`
- Browser (Chrome, real session): `/contact/?id=ppc` → `#forminator-module-194` is empty (0 fields, height 0). The right column is blank.
- `/contact/` without param → form renders (6 fields, 373px).
- Why: Forminator 1.58.4 `front.multi.min.js` → `forminatorLoader.init()` copies **every URL query param** into the `forminator_load_form` AJAX data (`new URLSearchParams(location.search).forEach((v,k)=> o[k]=v)`). `?id=ppc` overwrites `id: "194"` with `id: "ppc"`.
- Proof: POST `action=forminator_load_form&type=forminator_forms&id=ppc` → `{"success":false,"data":[{"code":"invalid_id"}]}`.
- So every PPC visitor (all ad URLs use `?id=ppc`) who lands on or keeps `?id=ppc` on /contact/ sees no form → no submissions → no conversions.
- On Oct 1 the test on /contact/?id=ppc worked, so this most likely started with a Forminator update after Oct 1 (now 1.58.4).
- Probably hits **any** URL param named like a load field (`id`, `type`, `action`, `nonce`…). Normal `gclid`/`utm_*` are just extra keys, harmless.

**Fix (no code):** WP Admin → Forminator → Forms → Contact Form (#194) → Edit → **Behavior → Rendering → turn off "Load form using AJAX"** → Update. The form then renders in the page HTML, so the URL param no longer matters. Clear WP Rocket / Hummingbird / LiteSpeed cache after.
- Verify: `/contact/?id=ppc` shows the form; test submit in GTM Preview → `form_success` → SS - Contact Form fires.
- Fallback if the toggle doesn't help: small snippet (WPCode) or ask PM to stop using `id=` (not realistic, DNI uses it).
