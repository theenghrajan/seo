Summary (from comments):
- GA4 Direct sessions jumped to 87,846 in September; 98.5% from Singapore, 2-second avg engagement, GA4 anomaly flagged from Sep 3.
- Smaller spikes from Brazil, Pakistan, Bangladesh, Vietnam (likely proxies).
- Bot is crawling paginated pages /product-category/gazebos/page/5/ to /page/13/+ (~3,800-3,990 sessions per page).

Note on plan: Country-based rules are available on the Cloudflare Free plan through WAF Custom Rules (Free includes 5 custom rules). A paid plan isn't required for Steps 3-4. (Country "Block" under the older IP Access Rules is Enterprise-only, so use Custom Rules instead.) Please confirm in the client's dashboard.

----------------------------------------
Step 1: Get access and confirm the site is proxied
----------------------------------------
1. Get Cloudflare access for the client's account (or have the client's developer follow these steps).
2. Go to DNS > Records and confirm the root domain and www records are "Proxied" (orange cloud). If they are "DNS only" (grey cloud), Cloudflare can't block anything.

----------------------------------------
Step 2: Confirm the bot traffic reaches Cloudflare
----------------------------------------
1. Go to Analytics & Logs > Traffic (or Security > Analytics), last 30 days.
2. Filter by Country = Singapore and check for a spike starting around Sep 3.
3. Also filter by Path contains "/product-category/gazebos/page/".
4. If the spike shows in Cloudflare, continue to Step 3.
   If Cloudflare shows NO matching spike, the GA4 hits are likely fake/ghost hits sent directly to GA4 (not visiting the site). Cloudflare can't block those. Stop and report back; the fix would be in GA4 instead (segments/comparisons excluding this traffic).

----------------------------------------
Step 3: Challenge traffic from the bot countries
----------------------------------------
1. Go to Security > WAF > Custom rules > Create rule.
2. Rule name: Challenge bot countries
3. Click "Edit expression" and paste:
   (ip.src.country in {"SG" "BR" "PK" "BD" "VN"} and not cf.client.bot)
   - "not cf.client.bot" keeps Googlebot, Bingbot and other verified bots allowed.
4. Action: Managed Challenge
   - Real visitors pass the challenge; bots fail it. Use "Block" instead only if the client confirms they have no customers in these countries.
5. Click Deploy.

----------------------------------------
Step 4: Protect the paginated category pages
----------------------------------------
1. Security > WAF > Custom rules > Create rule.
2. Rule name: Challenge gazebo pagination
3. Expression:
   (http.request.uri.path contains "/product-category/gazebos/page/" and ip.src.country ne "US" and not cf.client.bot)
   - Adjust "US" if the client sells to other countries (e.g. {"US" "CA"} with "not ip.src.country in").
4. Action: Managed Challenge
5. Click Deploy.

Optional (if bots switch to US proxies):
- Security > WAF > Rate limiting rules > Create rule (Free plan includes 1 rule).
- Match: URI Path contains "/product-category/gazebos/page/"
- When rate exceeds: 20 requests per 10 seconds, per IP.
- Action: Managed Challenge (or Block) for 10 seconds.

----------------------------------------
Step 5: Turn on Bot Fight Mode (optional)
----------------------------------------
1. Go to Security > Bots.
2. Free plan: turn on Bot Fight Mode. Paid plans: in Super Bot Fight Mode, set "Definitely automated" to Block or Challenge and keep "Verified bots" set to Allow.
3. Warning: Bot Fight Mode can't be bypassed with custom rules. If Google Search Console starts showing 403 errors afterwards, turn it off.

----------------------------------------
Step 6: Verify
----------------------------------------
1. Security > Events: filter by the rule names above and confirm Singapore/pagination requests are being challenged.
2. GA4 > Reports > Acquisition > Traffic acquisition: Singapore/Direct sessions should drop within 24-48 hours.
3. GSC > URL Inspection > Test Live URL on the homepage and one /product-category/gazebos/page/5/ URL. Page fetch should be "Successful" (confirms Googlebot isn't blocked).
4. Past September data in GA4 won't be removed. For reports, use a comparison/segment that excludes Country = Singapore.
